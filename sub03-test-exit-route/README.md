# ric-plt-submgr：生产启动注册测试退出入口（VUL-SUB-03）

- **组件**：o-ran-sc/ric-plt-submgr（验证提交 `98ebf666e797ee02a7b2946742ebcc4259252b4c`；运行栈 v0.10.1）
- **CWE**：CWE-489（活动调试代码暴露于生产）
- **结论**：CONFIRMED（真实源码树内测试确认退出行为）
- **影响**：进程终止（取决于 REST 端点实际可达性）
- **触发者**：能访问 submgr REST 端点的主体（RIC 平台内任意进程；若入口策略允许则更广）

## 成因

`pkg/control/control.go:167-173` 在**普通启动路径** `NewControl()` 中注册测试路由，对应处理器 `pkg/control/debug_rest_if.go:64-68` 的 restart 测试动作直接执行 `os.Exit(1)`。这不是内存安全问题，而是明确的测试退出能力被编入生产二进制且默认注册。

当前包装器负责请求来源提取与限流，限流并不能取消已允许请求的退出行为。

## 触发路径

1. 能访问 submgr REST 端点的主体发送对应测试动作的 HTTP 请求；
2. 处理器命中测试动作即执行 `os.Exit(1)`；
3. submgr 进程立即终止。

## 实测证据

真实 submgr 源码树内测试：路由命中即退出进程（`os.Exit(1)`）。

## 复现

测试源码 `crash_sub03_test.go` 与完整复现记录（命令、退出行为观察、影响边界）见本目录 [REPRODUCTION.md](REPRODUCTION.md)。

## 修复建议

生产构建移除该路由；测试注册放入专用 build tag 文件，默认生产文件不提供这类入口。如确需运维重启能力，走已有受控运维接口并明确访问控制，不直接复用测试处理器。
